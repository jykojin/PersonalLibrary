## 输出格式

```
### <pk>
《书名》是……（导语段，1–2 句）

分节标题一
 要点： 说明。
 要点： 说明。

分节标题二
 要点： 说明。
 要点： 说明。

这本书的独特价值
 要点： 说明。
 要点： 说明。

### <下一本的 pk>
（同上）
```

- `### <pk>` 的 pk 必须与输入的 pk 一一对应。**一本都不能漏，也不要写输入里没有的 pk。**
- 条目行以**一个普通半角空格**开头。**不要研究空白字节**，照抄样板即可。

## 硬要求

- 每段 **700–1000 个中文字符**。计法是**去掉所有空白后的字符数**（标杆样板恰为 694）。
  **每节写 3 条**（3/3/3），**每条说明 85–95 字**。这两个数是实测校准过的：
  三节各 2 条只有 620–660 字；3/3/3 但每条只写 70 字也只到 606–708 —— 都达不到下限。
  按 3/3/3 × 85–95 字写，稳定落在 720–870，一次过，不必返工
- 三个分节；**末节固定谈价值／局限／为什么值得读**
- 分节标题必须是**这本书特有的**，6–12 字。禁止「内容概览」「主题与特色」「阅读价值」这类通用词
- 纯文本。不要 `#` `**` `-` `*` `1.`（App 里是 `Text` 直出，markdown 会原样显示）
- **不许整段抄 `douban_intro`** —— 它是原料，必须提炼重写。连续重合 40 字以上判抄袭
- **不许编造**情节、人物、获奖、销量。资料没说的别写
- 不许出现「展开全部」「综合性读物」「创作或编著」「本书重点涉及」，正文不许含 `……`
- 书名带版本装饰时（`(共四册)`、`（精装）`、`/语文新课标…`），正文写**作品本名**即可

## 两条轨道

看输入文件的 `track` 字段：

- **track A** —— 原料充足。只用 `douban_intro` / `author_intro` 加你自己的可靠知识。
  **不要联网搜索**（联网会把整轮拖慢一个数量级）。
- **track B** —— 缺料。每本先用 `WebSearch` 搜「书名 + 作者」查证。
  判断是否同一本书要**对上作者**，只有书名对得上一律视为没查到。
  查不到就**不要硬写**：那本写成
  ```
  ### <pk>
  [资料不足] 原因简述
  ```
  留空是可接受的结果，编造不是。`AMIGO-` 开头的 ISBN 是用户自制编号（私人扫描书），
  网上大概率查不到，别硬凑。

## 效率要求

这是**写作任务**，不是研究任务。按契约直接写，不要反复推敲、不要探索仓库、
不要去读校验脚本。分 3–4 次 `Write`/`Edit` 落盘（每次追加几本），
避免一次生成过长被截断。

## 自检（这一步不是可选的）

```bash
cd /Users/joe/Documents/Claude/Projects/私人图书馆
python3 tools/ai_intro/pipeline.py ingest-text NNN
```

它会做两件事：报缺了哪些 pk，以及**逐条校验并列出不合格的段**。

**必须反复跑到它打印「校验：全部合格」且不再列出缺失 pk 为止。** 常见两类问题：

- `与豆瓣简介连续重合 N 字` —— 你抄了原料里的句子。把那一条**重写**，
  换说法、换切入角度，不要只改几个字。这是最常见的失败原因。
- `篇幅过短` —— 把该段补到 700 字以上。

标着「供参考，不必改」的是书名的繁简/中译名差异，**不用管**。

经验数据：自发跑过这条校验的批次 0 打回；跳过的批次每 25 本里约有 2 条抄袭被打回。
少跑这一步不会省时间，只会把返工推到后面。

## 返回值

**不要把介绍正文放进返回值。**
