# 图书信息补全升级（统一原子能力 + AI 智能补全）— 设计规格

**初版日期：** 2026-09-19

**最终修订：** 2026-09-22

**状态：** 已实现；最终回归与部署记录见实施计划

**目标：** 把单本补全做成一个可复用的深模块，供添加、编辑、单本、批量和微信读书同步共同使用；普通检索后自动以 AI 检索兜底，并提供可单独触发的 AI 智能补全。

**不涉及：** 封面能力、已有线下 `tools/ai_intro/` 管线、已有 AI简介存量重写。

**文档关系：** 本文是需求与设计的事实来源；代码分层、文件映射、TDD 记录、验证结果和部署方式统一记录在 [`../plans/2026-09-20-ai-enrichment-upgrade.md`](../plans/2026-09-20-ai-enrichment-upgrade.md)。

## 1. 最终需求

1. 单本智能补全必须是一项原子能力，调用者不再分别实现缺失判定、来源顺序、字段合并、日期转换和错误处理。
2. 普通检索严格按 **豆瓣 → Goodreads → Open Library** 顺序执行，只填空值，不覆盖用户已有内容。
3. **图书简介和作者简介不允许采用 Open Library**；Open Library 只补事实字段，也不再为简介额外请求 Works/Bio 接口。
4. 豆瓣解析新增译者提取。
5. 普通检索结束仍有空值时，在已配置 AI 的前提下自动运行 AI 智能补全。
6. AI 通过联网检索补事实字段和描述字段。每个采用值必须有可验证来源；没有来源、身份不匹配或无法确定时留空，不得凭模型记忆编造。
7. 唯一允许 AI 生成的字段是现有 `Book.bookIntroduction`，产品文案统一称为 **AI简介**；已有值不覆盖。
8. 添加页和编辑页在现有智能补全按钮旁新增“AI智能补全”；批量工具新增“批量 AI 智能补全”。
9. 微信读书自动同步也必须为缺少 AI简介的图书自动生成 AI简介；这会产生 AI 调用和 token 消耗，用户已确认接受。
10. 设置页支持 AI 平台、endpoint、API Key、联网方式和模型配置。默认平台为百炼，支持常见平台预设及自定义 OpenAI 兼容 endpoint。

## 2. 现状与改造原因

当前 `ISBNLookupService.smartFill` 已被以下四条路径直接调用：

| 现有调用方 | 现状差异 |
|---|---|
| `AddBookView.performSmartFill` | 用表单字符串判空；不认识豆瓣折叠残留；无出版日期和译者写回 |
| `EditBookView.performSmartFill` | 用 `Book.descriptionNeedsRefresh`；有日期转换和微信读书分支 |
| `DataMaintenanceView.batchEnrich` | 直接读写 `Book`；自己建作者简介缓存；逐本保存和取消 |
| `WeReadSyncService.sync` | 只为 `CB_` 用户导入书补描述；用 `isEmpty` 判定 |

查询扇出虽然集中在 `smartFill`，但缺失判定、写回、日期解析、本地作者简介、状态展示和重试语义仍散落在调用方。测试只能覆盖早退和结果结构，无法稳定验证多源优先级与入口一致性。

当前实现还有以下已确认问题：

- `smartFill` 的顺序是豆瓣 → Open Library → Goodreads，与新需求不同。
- Google Books 已从 `smartFill` 移除，但部分 UI 和 README 文案仍声称会查询 Google Books。
- `translator` 虽存在于结果结构和 needs 参数中，实际永远不会被赋值；它还会导致所有来源被无意义地跑完。
- `.error` 状态从未产生：网络错误被 `try?` 吞掉并显示为“未找到”。
- 有有效长度 ISBN 时，即使 ISBN 查询全部失败，也不会再用书名回退。
- 豆瓣书名搜索当前忽略作者并取第一条结果，历史数据已经出现过简介串书，必须增加身份核对。
- 批量任务无论命中与否都会写 `lastEnrichmentDate`，临时网络失败也不会自动重试。

## 3. 模块与 Interface

### 3.1 外部 seam：单本补全

所有调用方只依赖一个 Interface：

```swift
func enrich(
    _ draft: BookDraft,
    mode: EnrichmentMode,
    localAuthorDescription: String?
) async -> EnrichmentOutcome
```

建议模式：

```swift
enum EnrichmentMode {
    case full                 // 普通检索 → AI 兜底 → 缺失 AI简介时生成
    case aiOnly               // 跳过普通来源，AI 检索补空 + 生成 AI简介
    case aiIntroductionOnly   // 只生成 AI简介，供微信读书平台书自动同步
}
```

Interface 的不变量：

- 输入和输出均为值类型；模块不直接持有 SwiftUI 状态或 SwiftData `ModelContext`。
- 只填空值，不覆盖原值。
- 返回完整 `EnrichmentOutcome`，不直接保存数据库。
- 来源顺序、字段资格、证据验证、错误分类和 token 统计都封装在模块内部。
- 调用者只负责把表单或 `Book` 转成 `BookDraft`，再把 Outcome 写回。

### 3.2 `BookDraft` 是唯一缺失判定

`BookDraft.missingFields` 统一以下语义：

- 空字符串按缺失处理，判定前 trim。
- 作者为空或为“未知作者”算缺失。
- `totalPages <= 0` 算缺失。
- 图书简介或作者简介为空，或含豆瓣折叠残留“展开全部”，算缺失。
- AI简介仅空值算缺失；存量三节稿件不算缺失，不自动重写。
- ISBN 是检索锚点，不由 AI 写入；封面完全不进入本模块。

`BookDraft` 覆盖：书名、作者、译者、ISBN、出版社、出版日期、页数、定价、图书简介、作者简介、AI简介，以及仅供生成 AI简介使用的评分和备注。

### 3.3 内部 seams

远程依赖属于 true external，必须通过内部 port 注入：

- `BookMetadataLookup`：普通来源检索。生产 Adapter 为改造后的 `ISBNLookupService`，测试 Adapter 返回固定候选。
- `AIEnriching`：AI 检索与生成。生产 Adapter 为 `AIEnrichmentService`，测试 Adapter 返回固定证据、错误和 token 用量。
- `AICompletionClient`：OpenAI 兼容 HTTP。生产 Adapter 使用 `URLSession`，测试 Adapter 不访问真实网络。

测试从 `EnrichmentCoordinator` 的公开 Interface 观察结果；不再复制生产判定到测试里。

## 4. 普通检索阶段

### 4.1 顺序与回退

来源顺序固定为：

1. 豆瓣
2. Goodreads
3. Open Library

每个来源内部先尝试 ISBN；ISBN 缺失或该来源未命中时，使用书名 + 作者回退。书名结果只有在身份核对通过后才能采用：

- 书名规范化后匹配；允许版本说明、标点和繁简差异。
- 作者已知时必须匹配作者；仅书名相同不能视为同一本书。
- 结果存在冲突或歧义时，该来源记为未找到，不写字段。

ISBN 命中同样不是无条件可信，所有成功结果必须在进入字段合并前通过统一身份闸门：

- 来源独立返回 ISBN 时，必须与请求 ISBN 相同；去除连字符、空格并统一 `X` 大小写后比较，同时把同一本书的 ISBN-10 与 `978` ISBN-13 视为等价表示。
- 输入已有书名或作者时，即使 ISBN 匹配，也必须继续核对已知书名和作者，防止跳转或来源记录串书。
- 仅有 ISBN、而来源又没有提供可独立验证的 ISBN 凭据时，结果按未找到处理，不能把请求 ISBN 原样回填后当成验证证据。
- Open Library ISBN API 只有响应中存在请求 ISBN 对应的 key 才产生结果，因此该 key 视为来源侧 ISBN 绑定；豆瓣从详情页 `ISBN` 标签提取凭据；Goodreads 使用 JSON-LD 的 `isbn`；扫码兼容路径中的 Google Books 使用 `industryIdentifiers`。
- 身份拒绝首先发生在 `ISBNMetadataSourceAdapter`，早于 `SequentialBookMetadataLookup` 合并，因此添加、编辑、批量和微信同步共享相同行为。保留给扫码/快速添加的 `ISBNLookupService.lookup(isbn:)` 也必须在返回前经过同一 `BookIdentityMatcher.isbnMatches` 闸门，不得成为绕过路径。
- 书名 + 作者回退是独立的身份策略：在两者匹配时可接受同一作品的另一版本 ISBN，不把“版本不同”误判为串书。

字段采用“来源优先、逐字段首个合法值胜出”。高优先级来源缺少某字段时，低优先级来源只补该空字段。

### 4.2 字段来源矩阵

| 字段 | 豆瓣 | Goodreads | Open Library |
|---|---:|---:|---:|
| 书名 / 作者 | ✅ | ✅ | ✅ |
| 译者 | ✅ 新增 HTML 提取 | ❌ | ❌ |
| 出版社 / 出版日期 | ✅ | 有可靠结构化值才采用 | ✅ |
| 页数 | ✅ | ✅ | ✅ |
| 定价 | ✅ | 有可靠结构化值才采用 | ❌ |
| 图书简介 | ✅ | ✅ | **禁止** |
| 作者简介 | ✅ | 有可靠且身份匹配的资料才采用 | **禁止** |
| AI简介 | ❌ | ❌ | ❌ |

Open Library 改造要求：

- ISBN 路径不再调用 Works API 获取 description。
- 不再调用 Author Bio 接口。
- 书名搜索仍保留，用于 ISBN 缺失时补作者、出版社、页数和出版日期，但不得返回两类简介。

### 4.3 豆瓣解析

同一份豆瓣详情 HTML 一次解析出书名、作者、译者、出版社、出版日期、页数、定价、图书简介和作者简介，避免为两种简介重复搜索和下载页面。

译者从 `info` 区域“译者”标签后的一个或多个链接/文本中提取，统一以 `", "` 分隔；空值和页面装饰文本丢弃。

### 4.4 来源状态

Outcome 必须区分：未尝试、命中、未找到、可重试失败、不可重试失败、验证拒绝、取消。网络错误不能再伪装成“未找到”。

## 5. AI 智能补全阶段

### 5.1 AI 可写字段

AI 检索可以补以下空值：

- 书名、作者、译者、出版社、出版日期、页数、定价
- 图书简介、作者简介

AI 不写 ISBN、封面、阅读状态、评分、备注及其他用户数据。已有值一律不覆盖。

### 5.2 证据契约

AI 检索返回结构化 JSON；每个候选字段必须携带自己的来源 URL，而不是只给整次响应一个笼统 sources 数组。概念结构：

```json
{
  "fields": {
    "publisher": {"value": "...", "sources": ["https://..."]},
    "total_pages": {"value": 320, "sources": ["https://..."]}
  },
  "identity": {
    "matched_title": "...",
    "matched_author": "..."
  },
  "status": "ok"
}
```

采用闸门：

- `sources` 缺失或为空：丢弃该字段。
- URL 不是 `http/https`、是 AI endpoint 自身、格式非法：丢弃。
- 书名/作者身份不匹配：整次检索丢弃。
- 输入携带有效 ISBN 时，`identity.matched_isbn` 必须存在并与输入 ISBN 等价；即使书名已知也不能跳过该检查，ISBN 冲突或缺失时整次检索丢弃。
- 页数、价格、日期等类型或范围非法：只丢弃对应字段。
- 模型返回不完整 JSON：记验证拒绝，不部分猜测解析。
- 来源 URL 只是证据线索，不等于已验证网页正文；该限制必须在 UI 帮助和日志中如实说明。

### 5.3 AI简介生成契约

AI简介复用现有 `Book.bookIntroduction`。只有为空时生成，已有 2897 条左右的存量不重写。

生成前必须进行联网检索调研，并返回研究来源。没有有效来源或身份匹配失败时留空。提示词以 1000–1100 个非空白字符为建议目标，但不设最低验收字数；结构完整、来源有效的精炼正文可以采用，验证器保留 3000 字安全上限。正文为纯文本，不输出 Markdown。以下四方面是生成时可选择的写作方向，不是逐项必填内容或关键词验收清单：

1. **图书综合情况**：作者、背景、体裁、核心内容和定位。
2. **主题、特点、人物与写法分析**：人物只在适用时写；非虚构作品改写为关键案例、论证对象或思想人物；分析必须具体，不使用通用模板标题。
3. **阅读体验、感受与意义**：说明阅读节奏、可能的情绪或认知体验、现实或思想意义；不得虚构“我亲自读过”的经历。
4. **推荐、读后感、主题对比与扩展阅读**：可形成有依据的读后思考；只在确有可靠、相关材料时比较类似书或给出扩展阅读。

为保持模型协议和 App 排版稳定，响应仍使用 `overview`、`analysis`、`experience`、`recommendations` 四个 section；每段只需自然、具体地写最适合本书的内容，不要求覆盖该方向下的全部要点，也不按关键词判断是否齐全。

生成闸门：

- 四个 section 的结构、标题和正文有效且正文具有基本信息量；不验证四方面是否逐项齐全，也不对单个标题或单段正文设置固定字数下限。
- 精炼正文可低于建议目标；仅对空白、低信息重复内容和全文 3000 字安全上限进行相应校验。
- 导语中的书名与输入匹配，允许版本装饰、标点和繁简差异。
- 禁 Markdown、模板句、占位符、截断痕迹。
- 与图书简介连续重合不得达到 40 字；比较前去掉空白和标点。
- 对比和扩展阅读只作为可选正文方向，不要求单独的 `comparison_books` 结构；响应即使额外携带该字段，缺失、类型错误或内容残缺也不得阻塞整篇 AI简介。仍通过整篇 `sources` 要求模型基于联网调研，并明确禁止编造书、奖项、销量、人物或情节。
- 书名、作者等外部输入只放入 `<book_data>` 不可信数据区；控制指令只引用 `book_data.title` / `book_data.author`，不得直接插值外部文字。
- 第一次不过闸门时，把失败原因反馈给模型重试一次；仍失败则留空。

### 5.4 AI 阶段顺序

AI 阶段内部顺序固定为：

1. AI 检索补其余事实字段和两类简介。
2. 用普通来源结果 + AI 检索结果 + 评分/备注作为原料，研究并生成缺失的 AI简介。

这样 AI简介看到的是本轮最终草稿，不会在简介尚未补完时提前生成。

## 6. AI 配置

### 6.1 配置项

- 平台：默认百炼；初始预设包括百炼、OpenAI、DeepSeek、OpenRouter和自定义 OpenAI 兼容平台。
- Endpoint：百炼默认 `https://dashscope.aliyuncs.com/compatible-mode/v1`；预设可带默认值，自定义可编辑。
- API Key：使用 `KeychainService`，新增 key `com.personallibrary.ai.apikey`。
- 模型：平台提供系统推荐模型；可调用 `GET /models` 拉取列表供选择；拉取失败仍可手填模型 ID。
- 联网方式：由预设给默认策略，自定义平台可选无联网、`enable_search`、模型名 `:online`、OpenAI web-search 参数。

Endpoint、平台、模型和联网方式存 `UserDefaults`；密钥只进 Keychain。

### 6.2 可用性规则

- Endpoint 必须是 HTTPS，禁止 URL userinfo、敏感查询参数、fragment、localhost、环回、私网、链路本地和保留地址；查询参数只允许大小写不敏感的 `api-version`，其余一律拒绝，避免未知凭据明文进入 UserDefaults；重定向后也要重新校验。仅内置平台 Endpoint 与联网验证域名可兼容 VPN 的 `198.18.0.0/15` Fake-IP，自定义域名仍按保留地址拒绝。
- 未配置 endpoint/model/key 时，普通智能补全静默跳过 AI；AI 专用按钮置灰并引导设置。
- 配置的平台/模型不支持联网检索时，不允许运行 AI 检索或生成 AI简介，避免把模型记忆伪装成检索结果。
- “测试连接”验证认证和模型可调用；“读取模型”只负责列出模型，不代表模型支持联网。
- 百炼的 Chat Completions 搜索只保证检索增强，不保证读取指定 URL/API；因此百炼“测试连接”不得依赖 drand 原始 API。仅当 Endpoint 与内置百炼地址一致时，测试才使用百炼专用探针：开启强制搜索，并同时校验平台返回的输入 token 已达到搜索注入阈值、响应含合法外部来源 URL。编辑后的 Endpoint 和其他兼容平台仍使用不可预测随机信标验证，直至各平台提供更可靠的搜索执行信号。
- 连接测试使用独立的 30 秒全流程硬截止时间（包括 DNS、限流等待和重试）；单次探针最长 12 秒，可重试的网络错误或联网证据不稳定自动重试一次。百炼探针关闭深度思考并限制短输出，避免用简单的联网验证消耗长时间推理。
- 正式事实检索使用一个覆盖 4096 → 8192 两次尝试的 60 秒阶段硬截止并固定关闭深度思考；第二次请求的 HTTP 时限必须缩短为阶段剩余预算，不能重新获得完整 60 秒。AI简介为了保证调研与分析质量，百炼显式发送 `enable_thinking=true` 与 `thinking_budget=4096`，首轮使用 `max_completion_tokens=12288`，验证失败或截断后用 16384 重试；每次尝试均有独立 600 秒阶段预算和 HTTP 请求时限。客户端解码 `finish_reason`，绝不采用达到长度上限的残缺结果；`NSURLErrorNetworkConnectionLost (-1005)` 在同一请求内立即重试一次。截止后取消当前网络请求并返回可重试超时，截止前已经通过验证的字段必须保留。Endpoint、认证、模型和联网证据错误使用不同提示。
- 连接与联网验证成功后立即原子化保存当前配置、Keychain 密钥和验证标记，不再要求用户额外点击“保存设置”；返回添加、编辑或批量页时重新读取 AI 可用状态。测试期间锁定配置与保存入口，离页取消；持久化边界使用单调递增的存储版本执行比较并保存，拒绝旧测试结果覆盖已保存的新配置，也防止配置 A→C→A 时绕过检查。Keychain 凭据采用 update-or-add 写入，写入失败时恢复原凭据并保持原配置可用。
- 不在日志中记录 API Key、Authorization header 或完整用户备注。

## 7. 入口与行为

| 入口 | 模式 | 行为 |
|---|---|---|
| 添加页“智能补全书籍信息” | `.full` | 普通检索 → AI 兜底 → 生成缺失 AI简介 |
| 添加页“AI智能补全” | `.aiOnly` | 跳过普通来源，只运行 AI 阶段 |
| 编辑页“智能补全缺失信息” | `.full` | 微信读书已有值作为输入，再普通检索 → AI 兜底 → AI简介 |
| 编辑页“AI智能补全” | `.aiOnly` | 跳过普通来源，只运行 AI 阶段 |
| “批量补全纸质书信息” | `.full` | 保持纸质书候选范围，逐本调用同一 Interface |
| “批量 AI 智能补全” | `.aiOnly` | 未归档的纸质/电子/有声书均可进入 |
| 微信读书自动同步 | `.full` / `.aiIntroductionOnly` | 用户导入书保留外部补全；所有缺 AI简介的微信读书图书自动生成 AI简介 |

### 7.1 微信读书同步细则

- 微信读书平台书继续信任微信读书字段，不额外跑普通网页来源；只对缺失 AI简介运行 `.aiIntroductionOnly`。
- `CB_` / `isWereadUserImported` 图书在微信读书补全后运行 `.full`，补普通来源缺失值并生成 AI简介。
- AI简介候选不能只依赖 `wereadEnrichedDate == nil`：历史上已同步但 AI简介为空的微信读书图书，也应在下次同步进入 AI简介队列。
- AI 未配置时不标记为已尝试；以后配置完成再同步时仍可处理。

## 8. 批量与运行时

- 普通批量保持现有候选：未归档、纸质书、`needsEnrichment`、`lastEnrichmentDate == nil`。
- AI 批量候选：未归档、任意载体、`lastAIEnrichmentDate == nil`，并且 AI 可写字段或 AI简介仍有缺失。
- 顺序处理、并发固定为 1；普通来源每本之间保持 2 秒间隔，豆瓣继续使用全局 5 秒限速器。
- AI 调用本身较慢，不另加固定 sleep；429 使用服务端 `Retry-After` 或指数退避重试一次。`Retry-After` 仅接受有限数值并限制在 0–10 秒，缺失时可立即重试，`NaN`/`Infinity` 等非有限值统一按 1 秒处理。
- 复用 `BatchEnrichmentState.shared`，让后台封面任务继续礼让。
- 每本完成后立即保存；取消后不丢已经完成的书。
- UI 显示已处理/总数、当前书、成功/无资料/失败数和累计输入/输出 token。
- 普通来源阶段只有在“至少命中一个字段”或“所有已尝试来源都明确返回未找到”时才写 `lastEnrichmentDate`；临时网络失败、取消时不写，允许以后重试。

### 8.1 前后台生命周期

- 添加、编辑和批量补全在执行原子补全能力时申请 `UIApplication.beginBackgroundTask` 短时后台额度，并在操作完成或系统额度到期时成对释放。
- SwiftUI 的 `onDisappear` 与 `scenePhase` 没有可靠先后顺序，因此页面消失本身永远不作为取消依据；进入后台、弹出其他页面或生命周期重建均不得主动取消补全。
- 添加/编辑页补全期间禁止下拉关闭和保存，避免正在等待的表单被隐式销毁；“停止补全”和导航栏“取消”是明确的用户取消入口，仍须传播到网络任务。
- 系统后台额度到期只释放系统租约，不取消 Swift Task；App 回到前台后允许原任务继续等待或完成。
- 该设计只提供 iOS 允许的短时后台连续性。App 被系统终止或长时间挂起后无法保证客户端请求继续；若产品要求跨进程、无限时长保证，需改为服务端异步作业与任务恢复协议，不得伪造 audio/location 等后台模式。

新增 `Book.lastAIEnrichmentDate: Date?`：

- AI 阶段得到终态时写入：成功、经证据验证确认无资料、或生成重试后仍被闸门拒绝。
- 临时网络失败、401/403、最终 429、取消、AI 未配置时不写入，允许以后重试。
- 微信读书 `.aiIntroductionOnly` 的终态也写入；手动单本按钮不受时间戳限制，用户仍可再次触发。
- 已归档微信书不进入自动补全、AI简介或划线队列，也不会把评分、备注等存量数据发送到 AI Endpoint。
- optional Date 使用 SwiftData 轻量迁移，不进入 Excel 导入导出。

## 9. 错误分层

| 情况 | 单本行为 | 批量/同步行为 |
|---|---|---|
| AI 未配置 | full 模式跳过；AI 按钮提示设置 | 跳过 AI，不写时间戳 |
| 普通来源网络失败 | 记录该来源失败，继续下一个来源 | 继续当前书与下一本 |
| AI 普通网络失败/超时 | 显示失败，可重试 | 跳过本书，继续下一本，不写时间戳 |
| 401 / 403 | 提示凭据错误 | 立即中止整批，避免持续失败 |
| 429 | 按规则退避重试一次 | 仍失败则中止整批 |
| AI 字段无来源 | 对应字段留空 | 终态“无资料”，继续 |
| AI简介不过闸门 | 带原因重试一次，仍失败则留空 | 记录验证拒绝，继续 |
| 取消 | 保留已完成字段 | 停止后续书，不标记当前未完成阶段 |

## 12. 已知限制与风险

1. 模型返回来源 URL 不代表 URL 内容一定支持该字段；当前范围只验证 URL、身份和结构，不抓取全文做二次证据抽取。
2. 各平台联网参数不统一，平台预设会随供应商变化，需要让自定义配置可见且可诊断。
3. 自动同步和普通批量都可能产生费用；进度必须显示 token，用设置页明确说明。
4. 对比阅读仍可能出现“真实书名 + 虚假关系”。当前产品把它视为正文中的可选生成方向，不用独立结构化元数据决定整篇采用；整体来源 URL 只是研究线索，仍需用户人工判断具体对比是否可靠。
5. 一个 `lastAIEnrichmentDate` 只能表示“对当时目标字段完成过终态尝试”，不能表达逐字段历史；手动单本入口保留重试能力作为补偿。
6. AI 请求不再把预检后的 hostname 交给 `URLSession` 二次解析；传输层只拨号到本次解析且已通过公网策略校验的数值 IP，同时用原 hostname 执行 TLS SNI/证书校验和 HTTP `Host`。同源重定向必须重新解析、重新校验和重新固定，多个地址间的故障转移也只能发生在同一批已校验地址内。该实现不等同于完整 `URLSession`：不支持 PAC/HTTP 代理、HTTP/2/3 或自动内容解压，VPN Fake-IP 兼容性仍须真机验证。
7. iOS 只向普通前台 App 提供有限的短时后台执行额度；当前实现不会因切后台主动取消，并会在额度到期后保留任务等待回前台，但不能保证 App 被系统终止后继续。严格保证需要服务端异步任务。

## 14. 2026-09-21 AI 输出截断修订

- 真机出现事实检索和 AI简介“返回内容不是完整 JSON”；根因是旧实现未读取 `finish_reason`，且深度思考与最终正文共用不足的输出预算。

- AI简介提示词先改为全文目标 1000–1100 字并取消逐段 260–285 字死限；随后根据真机反馈把 1000–1100 字明确为建议目标，移除 900 字最低验收门槛。该阶段曾保留 1200 字安全上限，现已由第 15 节的 3000 字修订取代。
- HTTP 层对 `NSURLErrorNetworkConnectionLost (-1005)` 自动重试一次；取消仍立即传播，不改变 429 和超时语义。
- 模拟器使用 qwen3.7-plus 对《大一统的制度密码》执行真实联网生成，在约 128 秒后一次通过完整合同；密钥仅来自模拟器 Keychain，未进入源码、日志或测试 fixture。
- 安全复核后的资源边界：AI简介在重复窗口、语义和抄袭分析前先执行长度上限（当时为 1200 字，现按第 15 节为 3000 字）；普通元数据响应使用 5 MB 流式上限；豆瓣建议最多展开 5 个详情请求；归档微信书不再进入自动补全队列。
- 超时语义复核确认结构化任务组会等待不响应取消的底层工作；现改用锁保护的一次性 continuation 竞速，60/600 秒阶段截止会立即返回并取消底层任务。
- 归档隐私复核补出入队后的并发归档窗口；微信同步在 AI 和划线外部调用前分别重读持久层状态，读取失败时 fail-closed。

## 15. 2026-09-21 AI简介 3000 字与 Unicode 资源边界修订

- AI简介最大长度由 1200 放宽为 3000 个非空白显示字符；1000–1100 个非空白字符仍只是生成建议，不增加最低验收字数。
- “3000 字”继续按 Swift 扩展字形簇 `Character` 解释，符合用户看到的中文/Unicode 字数；资源安全不能只依赖该计数。
- Prompt 输入、AI 事实字段和 AI简介同时限制 Unicode scalar 与 UTF-8 字节。Prompt 截断逐个 `Character` 累计预算，遇到单个异常大的组合字形时在该字形之前停止，不能用 `prefix` 把整个异常字形保留下来。
- AI简介在重复窗口、抄袭等高成本分析之前检查 3000 字、scalar 与字节总预算；远端事实字段在进入 Draft 前执行相同的多维预算。
- OpenAI 兼容请求在 JSON 序列化后执行 256 KB 最终请求体闸门，超限时不发送；普通请求和正常中英文、组合字符保持可用。
- TDD 覆盖 3000 接受/3001 拒绝、组合附加符简介拒绝、组合附加符事实字段拒绝、Prompt 安全截断和超大 HTTP body 发送前拒绝。

- 同步任务的所有权属于 `WeReadSyncService.sync`：统一入口创建并登记实际核心 Task，外部页面只调用或取消，不再分别登记外层 Task。同步运行槽必须原子 claim，并以 run ID 限制 cleanup，避免竞态和旧任务清除新任务。

## 17. 2026-09-21 AI 网络固定地址与证据主机规范化修订

- `SecureAIHTTPDataClient` 的公网 DNS 校验与实际 TLS 连接现在使用同一批地址：基于 Network.framework 直接连接已校验的 IPv4/IPv6 数值地址，同时保留原域名用于 TLS SNI、证书身份和 HTTP `Host`。
- AI 传输仅实现当前 OpenAI-compatible 合同需要的 HTTPS GET/POST 与 HTTP/1.1；请求强制 `Accept-Encoding: identity`，响应头和正文有界，支持 `Content-Length`、chunked 和连接关闭定界，取消与单请求超时会关闭底层连接。
- 301/302/303/307/308 最多跟随 5 次；每一跳仍只允许同主机、同端口 HTTPS，并重新解析、验证、固定。一个地址连接失败时只在该次已验证地址集合内故障转移，绝不退回 hostname 拨号。
- 来源 URL 与 Endpoint 的主机比较先规范化 DNS 根尾点，并把 IPv4/IPv6 文本转换为二进制身份；等价 IPv6 压缩/展开写法不能再作为“外部来源”绕过自证限制。
- 单元测试使用可注入的固定地址传输/连接 seam，不访问真实网络；最终还需用模拟器已有 Keychain 配置和真机网络完成实际 TLS、VPN Fake-IP 兼容验证。

## 18. 2026-09-22 豆瓣跨版本译者补全修订

- 豆瓣当前详情页允许字段标签后的冒号位于 `</span>` 外；作者和译者解析必须消费该冒号，不能把 `:` 当成人名片段。
- 精确 ISBN 对应版本缺少译者时，如果书名包含明确的版本装饰，豆瓣来源使用去除版本装饰后的书名和原作者检索同一作品的其他版本。
- 跨版本结果仍须通过现有书名规范化和作者身份核验；只借用非空译者，不用旧版覆盖精确 ISBN 版本的书名、ISBN、出版社、日期、页数或定价。
- 《大便书（纪念版）》ISBN `9787536486003` 的豆瓣页没有译者；身份匹配的 2008 年版 ISBN `9787531723103` 提供译者“吴锵煌”，作为本次真实回归样本。

## 19. 2026-09-22 AI 事实非成功状态与无效 JSON 分层修订

- 百炼 `qwen-plus` 对《人生问答》查询译者时，可能返回语法完整的 `{"status":"error","identity":{...},"fields":{}}`；它不是 JSON 损坏，但也不是足以证明整本书或字段“未找到”的成功合同响应。
- 事实合同必须先独立解析 JSON，再区分 `status == "ok"` 与模型明确报告未成功；只有无法解析、必要结构缺失或真正截断才属于 `invalidJSON`。
- 已核实书籍但单个字段无法确认时，模型必须返回 `status:ok` 与空 `fields`；只有这种成功空结果才映射为“未找到可补充字段”。
- 有效 JSON 的非 `ok` 状态在同一事实阶段总预算内重试一次；仍非 `ok` 时返回“AI 未按约定返回可验证结果”，不能伪装成整本书“未找到”。
- 真正的残缺 JSON 仍按 4096 → 8192 扩容重试并在最终失败时记为验证拒绝，不放宽证据或身份闸门。

## 20. 2026-09-22 豆瓣非补零出版日期修订

- 豆瓣《大一统的制度密码》详情页返回出版年 `2026-8`；旧解析器只接受固定宽度 `yyyy-MM` / `yyyy-MM-dd`，因此会把该值丢弃。
- 这是格式类别问题：所有 `yyyy-M`、`yyyy-MM-d`、`yyyy-M-d` 都可能受影响，包括已有回归样本中的 `2017-7-1`。
- `PublicationDateParser` 现在接受一位或两位月份、日期，同时继续通过非宽松日期解析拒绝越界日期；年、补零年月和完整日期行为不变。
- 回归同时覆盖日期解析边界和豆瓣 → Adapter → `BookDraft.publishDate` 合并链路。

## 21. 2026-09-22 AI简介身份锚点与副标题兼容修订

- AI简介响应的 `identity` 固定增加字符串字段 `matched_isbn`；输入没有有效 ISBN 时该字段返回空字符串。输入包含有效 ISBN 时，响应必须返回等价 ISBN；缺失、类型错误或冲突均拒绝整篇简介。
- 作者继续要求身份匹配。书名优先精确匹配；只有 AI简介已有有效输入 ISBN 作为身份锚点时，才额外接受由半角或全角冒号明确分隔的“主标题 ↔ 主标题＋副标题”关系，例如《人生问答》与《人生问答：生老病死苦的三十个问题》。普通书目来源的共享身份匹配保持严格，不继承这项宽容。
- 普通字符串前缀不视为同书；相同 ISBN 和作者也不能让《人生问答续篇》之类无明确副标题边界的标题通过。
- 身份失败仍沿用 AI简介原有的一次自动重试；错误提示统一为“书名、作者或 ISBN 身份不匹配”。

## 22. 2026-09-22 空白出版信息诊断边界

- 页数、定价或出版日期为空不应一律解释为解析错误：上游书目页可能确实没有该字段，微信读书接口也不保证返回定价与出版日期，且当前微信数据结构不提供总页数。
- 历史 `lastEnrichmentDate` 只表示普通来源曾达到终态，不记录逐字段来源、拒绝原因或解析版本。因此仅凭数据库无法事后证明每个空值究竟是来源为空、身份拒绝，还是旧解析器丢值。
- 普通常规批量当前只选择纸质书，并跳过已有 `lastEnrichmentDate` 的记录；微信读书平台书按既定需求只自动生成 AI简介。历史解析器升级不会自动重跑已标记完成的记录。
- 本轮只读审计不修改用户数据库。若后续要自动修复历史空值，应新增可审计的“重新补全缺失事实字段”策略或版本化逐字段尝试记录，不能把未知值直接写成推测值。
